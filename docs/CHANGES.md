# CryptIRC changelog

## v0.5.20 (November 2026)

- Add eight inline reactions in channels and PMs on supported IRC connections. Choose a reaction again to remove it, and keep counts for the current browser session.
- Encrypt the emoji and message reference in protected chats. Confirm reactions via IRC echo and keep delayed echoes attached to the correct message.
- Add fireworks, confetti, balloons, and floating hearts to the active chat. Respect reduced motion and add a Message effects switch in Notifications.
- Start Signal-style encrypted DMs between compatible users on the same CryptIRC instance or through the TwistedNET IRCd bridge. Confirm new fingerprints.
- Scope DM sessions and trust to the IRC connection. Keep the draft and ask for consent before sending a first PM in plaintext when encrypted discovery is unavailable.
- Fix the channel and PM lock action so it opens encrypted chat unlock. Recover from stalled key lookups and offer retry or reload when needed.
- Keep notices after reading them until Clear. Sync read and clear state across tabs and keep stale saves from bringing back cleared notices.
- Add private in-chat latency alerts for the active network, with an adjustable threshold and an off switch. Add private CTCP alerts and separate VERSION and FINGER switches.
- Store /keepnick per network so it can reclaim a nick after reconnects, service restarts, or while the browser is closed. Use /unkeepnick to stop.
- Add 30 original static themes for a total of 257. Improve text and control contrast across the collection, including the encryption dialog.
- Switch Linux installs, updates, and source builds to a lighter build at 2 GiB or less of available memory. Keep manual low-memory and normal build overrides.
- Move the free hosted client and Linux installation steps to the top of the README. Update the installation guide and publish the release notes on CryptIRC News.
- Bump the web and desktop versions to 0.5.20. Verify 381 Arch testnet checks, browser and theme checks, and repeat independent reviews with Claude and agy.

## v0.5.15 (November 2026)

- Peer verification now uses encrypted state alone. The server removes old plaintext trust mirrors, and peers known only through those records prompt for confirmation again.
- Recent key changes trigger a fresh check of which conversations require encryption.
- File downloads require a session cookie or bearer header. Session tokens in links are rejected.
- Invite codes are write-only in the admin UI, HTTP API, and MCP. Use `new_registration_code` to set a code or `clear_registration_code` to clear it.
- Script CSP blocks inline event handlers. Sign-in, offline startup, password reset, and sandboxed HTML pastes retain their controls.

## v0.5.14 (November 2026)

- **Encrypted chat recovery.** A browser-generated recovery code protects E2E keys independently of the vault passphrase. Existing accounts migrate their stored E2E data when they set up the recovery code. CryptIRC blocks plaintext sends to known encrypted targets and shows shared keys in a separate dialog. Server-hosted uploads and pastes are unavailable in encrypted chats.
- **Expanded CryptIRC MCP.** The raw command tool accepts network-specific IRC verbs and IRCv3 message tags. The IRC server continues to enforce channel and operator permissions.
- **Network and account settings.** Read and update saved network settings, including auto-join, reconnect behavior, and quit messages. Network credentials are write-only. The new `cryptirc_settings` tool covers synced preferences, notifications, and bots. Server and link-preview settings require a CryptIRC administrator.
- **Upgrade.** Use **Unlock encrypted chats** or `/encrypt unlock` and save the recovery code for other devices. A web service update is enough. Refresh the tool list in your MCP client or start a new session to discover the updated tools.

## v0.5.13 (November 2026)

- **Chat translation.** Pick a reading language in **Settings → Translation**, then translate messages on demand or automatically as new messages arrive. Each conversation can override the incoming setting. Translations appear alongside the original text.
- **Website and X/Twitter previews.** Translate link-preview titles and descriptions, X post text, quotes and loaded thread entries. The preview links and media still work.
- **Outgoing translation.** Choose a target language per conversation or match a DM peer's latest detected language. Normal composer messages are translated when sent. Failed translations keep the original draft available for retry.
- **Google Cloud and LLM providers.** Enter a Google Cloud Translation Basic key, or use any of the LLM providers listed in Bots, including Perplexity and custom OpenAI-compatible endpoints. LLM credentials are encrypted in the vault and shared between Translation and Bots. The settings panel can test your provider with a sample phrase.
- **Encrypted conversations.** Automatic translation skips protected chats. Manual translation asks before sending encrypted chat or preview text to a provider.

Upgrade notes
- A web update enables translation support. An IRC core or IRC server restart is unnecessary. Users enable the feature and supply their own credentials.

## v0.5.12 (November 2026)

New
- **CryptIRC MCP.** Connect an external AI client over Streamable HTTP with a revocable token from **Settings → Profile → MCP access**. The ten tools can list IRC networks and channel members, read and search history, send channel messages and DMs, join and part, manage connections, run IRC commands with your regular permissions, and work with appearance settings and your notepad. History and notes require an unlocked vault. End-to-end encrypted conversations stay in CryptIRC.
- **Passkey sign-in.** Add a named passkey under **Settings → Profile → Passkeys**, then use the passkey picker to sign in with your device or a compatible security key. Enrollment confirms your current password. Password sign-in is still available, and the IRC vault uses its own passphrase.
- **Settings search.** Find controls across Profile, Security, Notifications, Networks, Themes, and Bots, plus the admin controls you have access to. Search accepts common typos and aliases. Use the arrow keys and Enter or tap a result to jump to the matching control.

Fixes
- The message composer keeps its size when focused on desktop. Its single-line chat field is marked separately from sign-in fields to reduce password-manager prompts. Desktop Enter, mobile Send, and IME composition keep working.
- Channels and DMs restore the message and scroll position you were reading when you switch back, even after new messages arrive or you load older history. Scrolling to the live tail resumes auto-follow.
- Your avatar stays visible on your own nick with long or colored vhosts. When a verified hostmask changes, other eligible CryptIRC viewers refresh the avatar for the new identity.

Upgrade notes
- The colored-vhost fix includes changes to the IRC core. Installing and starting the updated IRC core reconnects IRC networks once. Subsequent web-only updates can retain those connections.
- Configure the canonical HTTPS URL in `CRYPTIRC_BASE_URL` to enable passkeys and MCP token setup.

## v0.5.11 (November 2026)

Fixes
- Avatars now work right after a web-only update or restart. irc_core remembers what the IRC server announced when the connection registered (capabilities, bouncer signs, CLIENTTAGDENY) and hands it to the web on every attach, so connections no longer stay "unclassified" (no cross-server avatars, CTCP AVATAR unanswered) until they reconnect.
- A server's CLIENTTAGDENY list that is too long to store is now treated as denying all client tags, instead of possibly dropping the avatar denial.
- X preview test: the deadline test no longer fails on fast idle machines.

Upgrade notes
- Restart irc-core once after upgrading from 0.5.10 or older (this reconnects IRC once). After that, web-only updates keep avatars working.

## v0.5.10 (November 2026)

New
- Avatars now work across CryptIRC servers. If you share your avatar ("Share my avatar with people on other CryptIRC servers" — asked when you first upload; off for avatars saved before this version), other people's CryptIRC servers on the same IRC network show it in their nick list, WHOIS and nick menu.
- Instant detection: on networks with IRCv3 message-tags, CryptIRC users see each other's avatars within seconds of joining a channel via an invisible TAGMSG — no messages, clicks or WHOIS. Also announced via a client-only tag on your messages, CTCP AVATAR (KVIrc-compatible, answered only when asked) and IRCv3 draft/metadata-2 where the server supports it. Plain IRC clients see nothing.
- The viewer's own CryptIRC server fetches remote pictures (HTTPS, public addresses only, no redirects, size/rate limited), re-encodes them and serves them same-origin, so viewers' browsers never contact other servers. Remote avatars are bound to the nick's current user@host and dropped on NICK/QUIT/PART/KICK/host change.
- Seeing other people's avatars never depends on your own avatar settings; only "Show other people's avatars" and the admin switch hide them. Remote avatars are not shown on connections through a bouncer (or before a connection is classified).

## v0.5.9 (November 2026)

New
- User avatars: upload a picture in Settings ▸ Profile ▸ Avatar (PNG/JPEG/WebP, max 2 MB; re-encoded server-side to 128/48 px PNG with all metadata removed, original never stored). Other CryptIRC users of the same instance see it in the nick list, WHOIS and the nick menu — only when the server can confirm the nick's current holder is that account on the same IRC server (never by network name; never through a detected bouncer). Owner opt-out, viewer "hide others' avatars", admin on/off switch and per-user removal. See INSTALL.md.
- Rich X/Twitter link previews (off by default; nothing changes until an operator enables a provider): author, text, counts, photos, video/GIF, quotes, optional ThreadReaderApp threads, signed same-origin media fallback. Providers: X guest API (operator-supplied bearer) or the secret-free FixTweet API. Encrypted, DM and unknown conversations never auto-load. Requested and specified by hallucinate. See INSTALL.md and docs/x-preview-verification.md.

Fixes
- Your own "has changed hostname" line is no longer shown in every channel on every reconnect (networks whose services re-apply a vhost); other users' host changes are skipped when the host did not change.
- Replies and reload drafts can no longer land in a different conversation (exact-name rule; replies use the message's own conversation); drafts from the previous build are discarded.
- Pop-out windows stay pop-outs after F5 or a sign-out reload.
- After a web restart, replayed history no longer changes which nick/host the server believes is yours (this also feeds E2E routing, echo suppression and bots); replayed echoes, notices and joins/parts are judged by the nick you had at the time.
- Installers and update.sh hand /opt/cryptirc back to root safely (non-recursive, no symlink following, binaries replaced not chowned, rollback folder kept private) and refuse unsafe layouts with nothing changed; an identical irc_core copy no longer triggers a needless daemon restart.
